# frplus

版: **1.0.0** (2026-11-20)。ライセンス: GNU GPL v3 (`LICENSE`)。同梱の Freerouting は GPL v3 (`NOTICE.txt`)。

Freerouting を外側から補うツール。KiCad の基板を Freerouting に渡す前に入力を整え、
結果を KiCad の DRC で検証してから基板に反映する。Freerouting 本体は改造しない。

## インストール (KiCad だけが入っている Windows)

配布用の zip (`python make_package.py` で `dist/` にできる) を展開し、`install.bat` をダブルクリックする。
管理者権限は要らない。次のことをする。

- ツール本体と Freerouting の jar を `%LOCALAPPDATA%\frplus` にコピーする
- Java 25 以降が無ければ、Eclipse Temurin の JRE を取得して `frplus\jre` に展開する (約 60 MB、PATH は変えない)
- KiCad のツールバーにボタンを足す (KiCad を起動し直すと出る)

Python は KiCad 付属のものを使うので、別に入れる必要は無い。コマンドから使うときは
`"C:\Program Files\KiCad\9.0\bin\python.exe" -m frplus ...` とする。
`-m frplus doctor` で KiCad、Freerouting、Java が見つかるかを確かめられる。
消すときは `install.bat -Uninstall` (ボタンと `%LOCALAPPDATA%\frplus` を消す)。

## 必要なもの (自分で揃える場合)

- KiCad 9 (付属の python と kicad-cli を使う)
- Java 25 以降と Freerouting の jar。`freerouting/dev/*.jar` (開発版のビルド) があればそれを、無ければ
  `freerouting/freerouting-*.jar` (リリース版 v2.5.0) を使う。設定の `freerouting_jar` でも指定できる
- 開発版のビルド: Freerouting の master を取得し (検証したのは 2026-11-13 の 01db81c)、Java 26 しか無ければ
  `build.gradle` の toolchain を 26 に変えて `./gradlew.bat executableJar --no-daemon`。できた jar を
  `freerouting/dev/` に置く。完走率と仕上がりはリリース版よりかなり良い (下の表)
- Python 3.12 (標準ライブラリのみ)

## 使い方

```bash
python -m frplus check path/to/board.kicad_pcb
```

事前診断だけ行う (数秒)。出口を塞がれたパッドがあれば、塞いでいるものと対処を表示する。

```bash
python -m frplus route path/to/board.kicad_pcb
```

配線する。既定では元の基板に触らず、`<基板名>_frplus/` に作業用コピーと結果を作る。

```bash
python -m frplus apply path/to/board_frplus
```

結果を確認したあと、検証を通っている場合だけ元の基板を上書きする (同じフォルダに日時付きの
`.bak` を残す)。`route --apply` で配線と反映を続けて行うこともできる。

終了コード: 0 = 検証を通った、1 = 未接続・新しい DRC エラー・出口の無いパッドがある、2 = 実行できなかった。

### KiCad のボタンから使う

```bash
python -m frplus install-plugin
```

KiCad のプラグインフォルダに読み込み用のファイルを 1 つ書く。基板エディターで
「ツール → 外部プラグイン → プラグインを更新」を実行するとツールバーにボタンが出る。
ボタンは保存済みの基板ファイルに対して `route` を実行し、検証を通れば「基板に反映」を押せる。
反映後は「ファイル → 元に戻す」で読み込み直す。

## 何をするか

Freerouting が知らないこと・間違えることを、前後で補う。正否の判定は Freerouting の数字ではなく
KiCad の DRC で行う。

前処理 (Freerouting に渡す前)

1. 基板と `.kicad_pro` / `.kicad_dru` を作業フォルダにコピーする。元の基板には反映まで触らない。
2. ロック済みの配線を固定配線として DSN に書き出す。
3. ネットクラスの線幅・クリアランス・ビア径が基板の最小値を下回っていれば、最小値まで引き上げる。
4. 穴クリアランスを守らせるため、DSN の中だけビア外径を広げる (取り込み時に実寸へ戻す)。
   パッド径が穴径より少し大きい NPTH (キースイッチの位置決め穴など) も、KiCad が銅のあるピンとして DSN に出すので、
   DSN の中だけ「穴径 + 2 x (穴クリアランス - 銅箔クリアランス)」まで広げる。
   部品やパッドに個別に設定したクリアランス (KiCad の DSN 出力が落とすもの) も DSN に書き込む。
   内層の銅を持たないスルーホールのパッドは、DSN に表と裏の形しか出ないので、内層にも穴の分の形を足す
   (足さないと Freerouting が内層で穴を横切る線を引き、KiCad でショートになる)。
5. 内層にベタを持つネットの表面実装パッドのうち、まだ何もつながっていないものにビアを足す。
6. 配線もビアも禁止していないルールエリア (配置用エリアなど) を、配線禁止領域から外す。
   参照名が重複する部品 (ロゴの `G***` が複数あるなど) は、DSN と SES の取り込みの間だけ別名にする
   (KiCad の DSN 出力は参照名が重複すると失敗する)。基板の参照名は変えない。
7. パッド以外のレジスト開口、銅箔層の文字・図形、基板内側のくり抜きの周囲を配線禁止にする。
   パッドの上に図形で描かれたレジスト開口 (パッドが F.Mask を持たない部品) は、パッドのための開口として除く。
8. 出口の無いパッドを探す。ロック済みの配線やビアに囲まれていれば、塞いでいるものを表示して止まる。
9. パッドの内側で止まっている配線の端点を、パッド中心まで延ばす (DSN の中だけ)。

配線

10. 設定を変えた複数の案を並列に Freerouting で配線し、それぞれ取り込んで DRC で採点する。
11. 未接続が残れば、最良の案を引き継いでもう一度配線する (前回の配線は引き剥がしてよいものとして渡す)。ベタ経由でつながるはずだったのに
    切れているネットは、次回は通常のネットとして引き直させる。改善が止まったらやめる。

仕上げ (案ごとに実行)

12. Freerouting が絞った線 (ネットクラスの 75% や 50% の幅) をネットクラスの線幅に戻す。
    戻すとクリアランス違反になる線は細いまま残して報告する。
13. 配線で分断されたベタの島を、同じネットの島が重なる場所にビアを打ってつなぐ。
14. 宙ぶらりんの線とビア (ロックされていないもの) を消す。
15. DRC を実行し、未接続と「配線前より増えたエラー」を報告する。ロック済みの配線の先が未接続のまま残った
    ネットは、`release_nets` に入れれば引き直せると案内する (ロックはユーザーの意図なので勝手には外さない)。

## 設定

基板の隣に `<基板名>.frplus.json` を置く (または `--config` で指定)。すべて省略できる。

| 項目 | 既定 | 意味 |
|---|---|---|
| `release_nets` | `[]` | ロック済み配線を外して引き直させるネット。書いたものだけ外す |
| `plane_layers` | `[]` | ベタ専用にする層。信号を引かせない |
| `plane_fanout` | `true` | 内層ベタのネットのパッドにビアを足す |
| `on_trapped` | `"stop"` | 出口の無いパッドがあるとき。`"warn"` なら報告して配線を続ける |
| `unroute` | `false` | ロックされていない既存配線を消してから配線する |
| `variants` | `"auto"` | 並列に試す設定案。`auto` は 1 回目が `default` `nofanout` `noneck` `plain`、開発版のやり直しの回はコスト違いの `cheapvia` `cheapvia_dir` `ripup_low` `nofan_cheapvia` を足して 8 案 |
| `max_resume` | `3` | 未接続が残ったときに配線をやり直す最大回数 |
| `local_ripup_mm` | `3.0` | 全体の引き剥がしで改善しないとき、未接続の箇所からこの距離までの配線だけ引き剥がせる形でもう一度配線する |
| `resume_ripup` | `true` | やり直しのとき、前回の配線を引き剥がして引き直すことを許す。`false` なら前回の配線を固定して残りだけ引かせる |
| `max_passes` | `100` | Freerouting 1 回あたりの配線パス数の上限 (`route --max-passes N` でも指定できる)。改善が 10 パス止まれば、その前に Freerouting 自身が止めるので、行き詰まった基板は早く終わり、改善が続く基板は回り続ける |
| `timeout_sec` | `3600` | 止まらなくなったときの保険の時間上限 (秒)。時間切れでもそこまでの結果は使う。`null` で無制限 |
| `reroute_broken_pours` | `true` | ベタ経由でつながらなかったネットを通常のネットとして引き直す |
| `stitch_pours` | `true` | 分断されたベタの島をビアでつなぐ |
| `mask_keepouts` | `true` | レジスト開口や銅箔層の文字・図形の上に配線させない |
| `accept_errors` | `[]` | 配線で増えても反映を止めない DRC エラー種別 |
| `thermal_retry` | `4` | 完走したのに残ったエラーが熱逃げ (`starved_thermal`) だけのとき、最良の結果を作った回と同じ入力を、別の設定の案でこの本数まで配線し直す (良くなればそれを最適化する)。`0` でしない |
| `max_parallel` | `null` | 同時に動かす Freerouting の本数の上限。`null` は搭載メモリから決める (1 本 2 GB として、メモリの約 7 割まで)。入りきらない案は順番待ちになる |
| `via_in_pad` | `"auto"` | 同じネットのパッドの中にビアを打たせる。`auto` は元の配線がそうしていれば許可 (開発版のみ) |
| `via_touching_pad` | `"auto"` | 同じネットのパッドのすぐ隣にビアを打たせる。`auto` は同上 (開発版のみ) |
| `optimize` | `"complete"` | Freerouting の最適化段。`complete` は未接続が無くなってから 1 回だけ走らせる (配線中は止める)。`always` は毎回、`never` は使わない |
| `preset` | `null` | 基板メーカーの製造能力に合わせた下限。`jlcpcb-2layer` `jlcpcb-4layer` `jlcpcb-6layer` (下の「プリセット」) |
| `extra_args` | `[]` | Freerouting にそのまま渡す追加の引数 (実験用) |
| `freerouting_jar` | 自動 | jar の場所 |
| `java` | 自動 | java.exe の場所。省略時は同梱の `jre`、無ければ PATH の java (25 以降) |
| `kicad_bin` | 自動 | KiCad の bin フォルダ |

上限は時間ではなく回数で決める。時間で縛ると、速いマシンほど多くのパスを回せて結果が変わるため。
所要時間は基板とマシン次第で、OpenDrone (8 層、910 パッド) は 1 パス 1〜3 分かかる。並列に回すと 1 本あたりは
遅くなる (4 本で 1.7 倍) が、合わせた処理量は 2.3 倍になる。

## プリセット

設定の `"preset"` で、基板メーカーの追加料金なしの製造能力を下限として使う。基板の設計ルールやネットクラスが
これより緩いときだけ、配線中はこの値まで引き上げる (ビア径は結果の基板でも広げる)。ユーザーの設定より厳しい値を
緩めることはせず、元の基板の設計ルールも書き換えない。

| プリセット | 最小線幅 / 間隔 | ビア (穴 / 外径) | 穴と線 | 基板端 | パッド内ビア |
|---|---|---|---|---|---|
| `jlcpcb-2layer` | 0.10 / 0.10 mm | 0.20 / 0.45 mm 以上 | 0.20 mm | 0.20 mm | 打たせない |
| `jlcpcb-4layer` | 0.09 / 0.09 mm | 0.20 / 0.45 mm 以上 | 0.20 mm | 0.20 mm | 打たせない |
| `jlcpcb-6layer` | 0.09 / 0.09 mm | 0.20 / 0.45 mm 以上 | 0.20 mm | 0.20 mm | `via_in_pad` の設定どおり (樹脂充填が既定の工程) |

- 値は JLCPCB の [PCB Capabilities](https://jlcpcb.com/capabilities/pcb-capabilities) (2026-11-17 に確認) の標準の最小値。
  銅箔は外層 1 oz、内層 0.5 oz (同社の既定) を想定している。2 oz にするなら、ネットクラスを自分で広げること
  (2 層 0.16 mm、多層 0.15 mm)
- ページで追加料金の条件が書かれているのはビアだけ (穴 0.1 / 0.15 mm、または穴 0.2 / 0.25 mm でビア外径 0.45 mm 未満は割高)。
  線幅などは追加料金の記載が無いので標準の最小値をそのまま使った。ネットクラスのビアの穴がこれより小さいときは
  注意を出す (穴径は DSN の中では変えられない)
- 基板端は外形をルーターで加工する場合の値。V カットなら 0.4 mm なので、基板の設定で広げること
- 基板の層数とプリセットの層数が違えば注意を出す
- 作者の 4 層基板 (非公開、事前配線なし) は `jlcpcb-4layer` で 77 秒で完走、新規エラー 0

## 構成

- `frplus/kicad_side.py` — 基板の読み書き。KiCad 付属 python で動く。pcbnew に触るのはここだけ
- `frplus/dsn.py` — DSN の前処理、SES の結果を DSN へ書き戻す処理、ルールの読み取り
- `frplus/geom.py` — 出口の無いパッドの検出、内層ベタへのビア配置
- `frplus/kicad_plugin.py` — KiCad のツールバーボタン
- `frplus/tools.py` — KiCad、kicad-cli、Freerouting の呼び出しとログ解析
- `frplus/route.py` — 全体の流れ

## 知っておくこと

- 線幅はネットクラスどおりになる。電源を太くしたいなら、KiCad 側でネットクラスを設定しておくこと。
  ネットクラスが 1 つしか無い基板では、電源も信号と同じ幅で引かれる。
- KiCad の SES 取り込みは、部品を SES 記載の位置へ動かす。DSN を出した基板と取り込む基板は
  同じものにすること (このツールは同じ作業用コピーを使う)。
- Freerouting v2.5.0 は存在しない設定名を警告だけで無視する。このツールはそれをエラーにする。
- Freerouting の利用統計送信は常に無効にして起動する。
- Freerouting は、ビアと「同じネットの」パッド・ビアの間にもクリアランスを要求する。KiCad では
  違反にならない配置でも、Freerouting はそこにビアを打たない。手で置いたビアがこれに当たると
  「pre-existing clearance violation」と警告される。このツールの診断とビア配置はこの規則に合わせてある。
  開発版ではこの制限を外せる (`via_in_pad` `via_touching_pad`)。開発版は基板に残っているビアを見て自動で
  決めるが、配線を消してから渡すと判定材料が無くなるので、このツールが消す前に数えて明示的に渡す。
  配線の無い新しい基板では `auto` は禁止になるので、パッド内ビアを使う設計なら `true` を指定すること。
- リリース版の Freerouting v2.5.0 は決定的で、同じ入力からは同じ結果しか出ない。開発版も含め、設定を変えた案を並べて最良を選ぶ。
- 出口の判定は、基板外形を外接矩形で見て、キープアウト領域は見ない。複雑な外形では診断がずれることがある。
- KiCad のボタンは KiCad 9.0.9 の画面上で動作を確認してある。
- `tests/compare.py` は人手配線と自動配線の配線長・ビア数・線幅を比べる。`tests/near.py` は未接続箇所の周辺を列挙する。

## 試した基板

配線をすべて消してから、既定の設定で自動配線した結果。Freerouting は開発版 (master の 01db81c をビルドしたもの)、
Windows、メモリ 64 GB のマシン。

| 基板 | 規模 | 結果 | 時間 |
|---|---|---|---|
| 作者の 4 層基板 (非公開) | 4 層、277 パッド | 未接続 0、新規エラー 0 | 約 1 分 |
| pic_programmer (KiCad 同梱) \* | 2 層、247 パッド | 未接続 0、新規エラー 0 | — |
| multichannel_mixer (KiCad 同梱) \* | 2 層、327 パッド | 未接続 0、サーマル接続のエラー 1 | — |
| StickHub (KiCad 同梱) | 2 層、16x40 mm に 278 パッド、45 度配置の QFN | 未接続 0、新規エラー 0 | 約 11 分 |
| OpenDrone AIO FC F405 \* | 8 層、34x34 mm に 910 パッド | 未接続 0、新規エラー 0 | 約 2 時間 |
| Ferris 0.1 (分割キーボード、左右 2 枚を 1 つに並べた外形) | 2 層、424 パッド | 未接続 0、新規エラー 0 | 約 4 分 |
| Lily58 Lite Rev3 | 2 層、218x160 mm | 未接続 0、新規エラー 0 | 約 9 分 |
| OpenDeck v2.2.1 メイン基板 | 2 層、832 パッド | 未接続 0、熱逃げのエラー 20 | 約 37 分 |

\* は 1.0.0 より前の版で測ったもの (その後の修正で、この基板に渡す内容は変わっていない)。

- 元の配線がパッドの中や隣にビアを打っていれば、それに合わせて許可する (`via_in_pad` / `via_touching_pad` の `auto`)。
  StickHub はパッドの隣へのビアを許可しないと完走しない。配線の無い新しい基板でパッド内ビアを使うなら `true` を指定する。
- リリース版の Freerouting v2.5.0 でも動くが、完走率はかなり下がる (以前の版での比較で、StickHub は未接続 9、OpenDrone は 80)。
- 開発版の Freerouting は、同じ入力でも実行ごとに結果がばらつく。上の表は 1 回の結果。
- 大きい基板では、1 本の Freerouting が保険の時間上限 (`timeout_sec`、既定 3600 秒) に当たることがあり、
  結果がマシンの速さに少し左右される。当たったときは結果に注意を表示する。

### 人手で一部を引いてから自動配線した場合

元の手配線のうち、電源と USB のネットと、24 ピン以上の部品のファンアウトだけをロックして残し、残りを自動配線した
(`tests/make_partial.py`)。StickHub は未接続 6 (すべて USB ハブの差動ペア)、OpenDrone は未接続 11 で、どちらも
配線なしより悪い。ロックした短い線の先端につなぐ形になり、そこで詰まる。ロックするなら相手のパッドまで引き切った配線にすること。
詰まったネットは結果に表示し、`release_nets` を案内する (混み合った場所では、ロックを外しても片付かないことがある)。

### 既知の制約

- Freerouting はベタの熱逃げ (スポーク) を考えずに、ベタにつながるパッドのすぐ脇へ他ネットの線を通す。
  GND の熱逃げのパッドが多い基板では `starved_thermal` が残ることがある (OpenDeck で 20 件)。
  完走して残ったのがこのエラーだけなら別の案でやり直す (`thermal_retry`) が、減らないこともある。
  許容して反映するなら `accept_errors: ["starved_thermal"]`。
- 配線禁止にする領域 (レジスト開口、銅箔層の文字) は外接矩形で近似している。
